# 第22章｜最短的路，为什么不能永远沿眼前最短走

假设你站在一座陌生城市的十字路口，导航告诉你：

左边这条路只有一公里，右边这条路有两公里。

如果只相信眼前的数字，你会选左边。

可万一左边一公里之后，是一条还要绕行一百公里的道路；右边两公里之后，却只需再走两公里就到终点呢？

最危险的错误，不是你不会计算一加一，而是你**把局部最短，误当成了全程最短**。

上一章我们刚学会如何用最小生成树把所有城市接起来。那时，数学家关心的是全体线路的建设成本。现在目标变了：只从一个起点出发，去另一座城市，走过的**路径权重之和**必须最小。

这两道题看上去都在挑便宜的边，实则完全不同。[GT22-01]

## 一｜五条线路足以毁掉直觉

先给出一个不涉及历史人物的教学反例。道路有方向，费用写在箭头上：

- A → B：1
- B → T：100
- A → C：2
- C → T：2

如果你每次只选择**当前地点出发最便宜**的边，那么从 A 出发会先走 A → B，因为 1 小于 2。

下一步只有 B → T，费用 100。

总成本：

\[
1+100=101。
\]

但另一条路线 A → C → T 的费用是：

\[
2+2=\boxed{4}。
\]

整整差了九十七。

所以，「每一步挑最便宜的下一段路」是错误策略。

甚至「上一章最小生成树选出的线路」也未必能给我们从 A 到 T 的最短路线。生成树最优的是**一整套连接的总价**，不是树上每一对点之间的距离。[GT22-02]

真正的问题已经很清楚：

不枚举所有可能路径，怎样得到一个可以证明正确的最短路算法？

## 二｜把「最短」写成一份可以不断修正的账

我们用一张有向带权图 \(G=(V,E)\) 表示交通网。

设 \(s\) 是起点，\(w(u,v)\) 是从 \(u\) 到 \(v\) 的边权；每条路径的权重，是沿路所有边权之和。

定义

\[
\delta(s,v)=\min_{P:s\leadsto v}\sum_{e\in P}w(e)
\]

为从 \(s\) 到 \(v\) 的真正最短距离。若不可达，记为 \(\infty\)。如存在从起点可达且能反复影响目标的负权回路，则某些点的有限最短距离根本不存在，稍后再谈。

但一开始我们并不知道 \(\delta\)。算法只能维护一张暂时的表：

\[
d(s)=0,\qquad d(v)=\infty\;(v\ne s)。
\]

每当发现一条可能更便宜的到达方式，就修改表格。

若存在边 \(u\to v\)，而

\[
d(v)>d(u)+w(u,v)，
\]

则把 \(d(v)\) 更新为 \(d(u)+w(u,v)\)。

这一步叫作**松弛**（relaxation）。[GT22-03]

为什么叫松弛？因为我们起初对到达 \(v\) 的成本估计过高，现在发现了更好的路线，于是放宽此前的记录。

这也告诉我们一个重要区别：**暂定距离可以变小；真正最短距离并不会因为程序运行而改变。**

已知每一项有限的 \(d(v)\) 都由某条实际起点路径构成时，它还是对应真正最短路成本的一个上界。我们不是凭空创造了成本，而是在不断寻找更好的可行路径。

## 三｜一张能算到最后的路线表

为了不让「算法」停留在抽象符号里，我们使用另一张自制网络：

| 有向边 | 费用 |
|---|---:|
| A → B | 4 |
| A → C | 1 |
| C → B | 2 |
| B → D | 1 |
| C → D | 5 |
| D → E | 3 |
| B → E | 7 |
| C → E | 12 |

要从 A 出发，计算到每个城市的最短距离。

初始化：A 为0，其余均为无穷大。

观察 A 的两条出边，得到 B 为4、C 为1。此时，**暂定距离最小的未处理节点**是 C，而不是 B。

从 C 向外松弛：

- 到 B 的新成本是 \(1+2=3\)，比先前4更好，更新；
- 到 D 的成本暂时是 \(1+5=6\)；
- 到 E 的成本暂时是 \(1+12=13\)。

接下来处理 B，因为它的暂定距离现在是3：

- 经 B 到 D：\(3+1=4\)，将6改为4；
- 经 B 到 E：\(3+7=10\)，将13改为10。

再处理 D：经 D 到 E 是 \(4+3=7\)，将10改为7。

最终得到：

\[
d(A)=0,\quad d(C)=1,\quad d(B)=3,\quad d(D)=4,\quad d(E)=7。
\]

A 到 E 的路线是：

\[
A\to C\to B\to D\to E
\]

总费用 \(1+2+1+3=\boxed7\)。[GT22-04]

这套过程与前面的错误贪心，有一处根本差别：**每次选择的是从起点出发的累计暂定成本最小者，而非从脚下出发最便宜的下一条边。**

正是这次改写，打开了通向 Dijkstra 算法的大门。

## 四｜为什么「暂定最小」可以变成「永久正确」

假定所有边权都**非负**。

从 A 出发，我们每次在尚未确定答案的顶点里，取暂定距离最小的 \(u\)，把 \(u\) 的距离标记为已确定，再用它松弛邻边。

这就是通常所说的 Dijkstra 单源最短路算法。

但一个算法不能靠「看起来正确」站稳脚跟。为什么我们可以在选中 \(u\) 的瞬间断言：以后再怎么绕，也不会找到更短的路？

反证一下。

假设 \(u\) 刚被选中，却存在一条真正更短的从起点到 \(u\) 的路径。沿着那条路径走，找到**第一个尚未被确定的顶点** \(y\)，它前面的一个顶点 \(x\) 已经确定。

当 \(x\) 被处理时，我们本应通过边 \(x\to y\) 使

\[
d(y)\leq \delta(s,x)+w(x,y)=\delta(s,y)
\]

成立；而任何有效的暂定路径又不能低于真正最短路，所以实际上 \(d(y)=\delta(s,y)\)。

从 \(y\) 往后通向 \(u\) 的剩余边权都非负，因此

\[
\delta(s,y)\leq \delta(s,u)。
\]

如果那条路径真的比当前 \(d(u)\) 更短，则

\[
d(y)=\delta(s,y)\leq\delta(s,u)<d(u)。
\]

可算法明明选择了暂定距离最小的 \(u\)。矛盾！[GT22-05]

所以每次确定的距离都是真的。

这段论证里最不显眼、却最决定性的条件，就是**边权非负**。没有它，路径绕出去以后还可能借由负权边把成本拉低，刚刚封存的数字就不再安全。

请记住这个因果链：

**非负边权 → 进一步行走不会让累计成本突然下降 → 最小暂定距离可以被安全确定。**

## 五｜1959年的论文：戴克斯特拉实际上写了两个问题

1959年，Edsger W. Dijkstra 在 *Numerische Mathematik* 第1卷发表短文 *A Note on Two Problems in Connexion with Graphs*，页码269—271。[GT22-06]

标题里的「两个问题」不是修辞。

原论文的第一个问题，是构造**总长度最小的连接树**；这正与前一章的最小生成树对应。

第二个问题，才是从一个指定点到另一指定点的**最短路径**。把这两项工作放在同一篇短论文里，今天读来反倒像是一堂精心安排的反混淆课：总线路费用最小，与某一条路线最短，从目标函数开始就不是同一回事。

不过，不能因此倒过来宣称两道题都由 Dijkstra 在1959年首创。前一章已经看到 Borůvka、Jarník、Kruskal、Prim 更早的工作。原论文参考文献也列出了相关的最小连接和网络流研究。

同样，今日教材里用优先队列写出的伪代码和复杂度分析，是后来的算法工程表达，不能一字不差地当成1959年论文原文。

数学史真正值得看见的，是**明确的算法问题、可执行的步骤与正确性的理由**开始并排出现。

## 六｜没有一个孤独的发明者：福特、贝尔曼和摩尔的路线

1950年代，路径优化并不只有一种算法方案。

Lester R. Ford Jr. 在1956年 RAND 报告 *Network Flow Theory* 中提出了通过反复调整路径标号来改善距离的方案。Richard Bellman 则在1958年《应用数学季刊》的 *On a Routing Problem* 中，从动态规划和递推逼近的角度研究城市间的最优路线。[GT22-07]

Edward F. Moore 的 *The Shortest Path Through a Maze* 后来收入1959年出版的国际开关理论讨论会论文集（第二卷，第285—292页）。它与无权图逐层搜索、最短路线的算法传统关系密切。[GT22-08]

现代叙述往往使用「Bellman–Ford 算法」这个联合名称。但不能简单把这个名称当成两位作者在某一天共同完成了一份完全相同的程序：其原始问题背景、标号过程和后世统一后的版本存在区别。

这里尤其不要把「Moore 的会议年份」与「论文集出版年份」随手混用；本章采用可核对的1959年出版书目，并不虚构其具体宣讲现场。

这些不同研究路线最终为我们留下两种重要思路：

一种是 Dijkstra 式的：在非负权条件下，按照累计暂定距离选取可以永久确定的顶点。

另一种是 Bellman–Ford 式的：让边不断获得放松旧标号的机会，不急于宣布某一个顶点的距离永远不变。

两种思路对应着不同的前提、证明和代价。

## 七｜一道负权边，就能使原来的证明坍塌

还是一张三点有向图：

- A → B：2
- A → C：5
- C → B：−4

A 到 B 看起来有一条直接花费2的边。

但经 C 绕行：

\[
5+(-4)=1。
\]

所以真正最短路是 A → C → B，费用为1。

如果照搬刚才的 Dijkstra 标准策略：从 A 更新 B 为2、C 为5，然后先把 B 的距离2确定，就会错过之后通过 C 改进为1的机会。[GT22-09]

请注意，这个反例**没有负权环**。所以我们没有借助「无限循环赚取负费用」来作弊；只是让一条负权边打破了贪心的安全条件。

而 Bellman–Ford 的标准现代形式，可以处理**有负权边但没有从起点可达的负权环影响最短距离**的图。

它的方法是：反复扫描全部边、执行松弛。经过最多 \(|V|-1\) 轮完整扫描，可以找到所有有限的最短距离，因为在不存在相关负权环时，总能选取不重复顶点的最短路径，它至多有 \(|V|-1\) 条边。[GT22-10]

如果第 \(|V|\) 轮仍能改进某个可达标号，则说明有从起点可达的负权环（或有相关距离仍受其影响），因而不能继续把所有结果当作有限最短距离。

这并不是宣称有负边的图就一定无法求最短路。真正需要区分的是：

**负边可以存在，负环可能使最短值不存在；Dijkstra 的固定最小标号方法则需要非负边权。**

## 八｜什么时候该用哪种方法

在无权图中，每条边都相当于一步。广度优先搜索（BFS）逐层扩张，找到的就是边数最少的路线。这时我们根本无需复杂的权重运算。

在非负加权图中，Dijkstra 利用「暂定距离最小者可以确定」的性质，配合优先队列可以高效处理大图。常见的二叉堆实现给出 \(O((|V|+|E|)\log|V|)\) 量级的运行时间，具体界依赖数据结构和实现。[GT22-11]

在允许负权、且关心负环检测的单源最短路问题中，Bellman–Ford 标准实现需要 \(O(|V||E|)\) 时间，代价更高，却换来不同的适用边界。

假如道路费用会随着时间改变，还需要重新建立模型；静态图中的一条边权不自动覆盖拥堵、出发时刻、通行限制等动态问题。

所以最重要的从来不是背出一个算法名字，而是先看清三件事：

你优化的到底是哪个对象？

你对边权和图结构做了什么假设？

算法停止时，凭什么相信它交出的数字不会再被推翻？

## 九｜从「一条路最短」，走向「整张网能承载多少」

到这里我们已经拥有两种不同的贪心：

第21章的最小生成树用割性质，确保便宜的边不会破坏全局最优的连接方案。

第22章的 Dijkstra 利用非负权，确保最小的累计暂定距离可以被永久确定。

它们的共同点，不是「贪心总会成功」，而是**每一步都需要可证明的安全条件**。

可如果把问题再改一次，事情又会复杂许多。

假如每条线路不再有「通行成本」，而是有「每小时最多能通过多少货物」的容量，单独找一条最短路线就不够了。你可以同时走许多条路，但所有路线共享某些瓶颈。

一条路最短，无法回答整个网络能运走多少东西。
