# 分章撰写协议｜盐选式知识叙事 × 非虚构证据约束

## 0. 禁止直接由占位稿改成“终稿”

执行写作前必须读取仓库`AGENTS.md`、`workflow.json`、`docs/contracts.md`，以及`chief-narrative-editor`、`genre-history-science`、`fact-research`、`nonfiction-architect`、`nonfiction-writer` Skills 和对应prompt。研究、架构和正文是不同阶段；状态只由明确审查后的事件更新。

## 1. 每章固定的阅读节奏

1. **冷开场（约5%—8%）**：提出有史料来源的技术矛盾或可复现反例，不能编造历史场面。
2. **旧世界的合理性（约12%—18%）**：上一代方法能做什么；当时的科学家有什么数据、算力和理论工具。
3. **第一次裂缝（约12%—18%）**：给出具体失败情形、边界条件或竞争模型。
4. **关键转折（约20%—25%）**：解释新的模型结构、训练办法或评估方式，并准确署名。
5. **可见的验证（约15%—20%）**：1个读者可手算的例子+论文实验设置/结果支持范围。
6. **反面证据与代价（约10%—15%）**：弱点、未解决问题、当时的不同观点。
7. **认知回报与新问题（约5%—10%）**：用一句话收束本章理解，打开下一章真实问题。

百分比是编辑建议，不是机械评分法。

## 2. 每章三层科学解释

- **直觉层**：少量具体例子（如XOR、卷积核、梯度链、attention权重），声明是教学简化。
- **机制层**：输入、输出、参数、优化目标、训练信号、评测指标说全。
- **边界层**：指出此模型并不能解决什么、后来为什么需要其他路线。

数学公式必须解释变量、前提与极端情况；不要拿随意手写的演示替代论文可复核性能。

## 3. 三层悬念，不作假反转

- **注意力**：利用真实悖论（“层数更深，为何误差反而升高？”）。
- **期待**：每一节交付一小段新的可解释信息，而不是用标题党断言。
- **价值**：章节尾声回答开头问题并指出机制局限；以**问题—方案—证据**推动阅读。

### 特别禁止

不得自拟“他望着屏幕喃喃自语”之类真实人物戏剧化对白；不得声称未经核实的实验室夜谈；不得把营销数字改成独立研究数据；不得抄长段论文原文或未授权图像。

## 4. 研究与验收清单

- [ ] 每个核心历史主张有source_id、原始出处、页面/图/表位置、发表版本。
- [ ] 技术机制经独立推导；现代回译明确，历史人物当时不可能知道的术语不被放进其口中。
- [ ] 关键结果注明基准、样本量、评价指标、比较方法、日期。
- [ ] 涉争议归属至少有可靠二手来源与竞争解释。
- [ ] 每章为历史主张生成`draft/NN.claims.json`，未核主张单列。
- [ ] 跨章数字、时间、术语与前文一致；由`continuity-audit`核查。
- [ ] `developmental-editor`独立审稿，修订后重新两道复审。
- [ ] 通过gate后才能`line-edit`、`final-approval`与包装；不自动宣称对外发布。

## 5. 续写交接模板

**本章解决**：……  
**这次新证据**：source_id + 原文位置……  
**哪些不能断言**：……  
**下一章真实问题**：……  
**引用与审校状态**：待核/已核；修订版本……

一批三章完成后检查：第一章留的疑问是否被第二章真实回答，第三章是否把知识线索推进到下一批，而非无意义“下回分解”。
